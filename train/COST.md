# 教师蒸馏成本指南（train/COST.md）

> 目的：把"花了多少钱、花在哪、怎么少花"变成可测量的事。所有数字来自本机跑批日志（`train/artifacts/*.log`），
> 币种人民币，单价随官方调整 —— 用环境变量覆盖后再看估算：`TEACHER_PRICE_HIT` / `TEACHER_PRICE_MISS` / `TEACHER_PRICE_OUT`（元/百万 token）。

## 实测用量（截至 v3 数据集）

| 阶段 | 调用次数 | 输入 tok | 输出 tok |
|---|---|---|---|
| v2 剧本生成（600 例，成 554） | 585 | 367,520 | 694,115 |
| v2 教师蒸馏（→ 675 对） | 773 | 1,715,279 | 163,101 |
| v3 剧本生成（1800 例，成 1773） | ~5,300 | ~3,500,000 | ~6,700,000 |
| **v3 增量蒸馏（→ 累计 2,795 对）** | **3,123** | **7,046,965** | **728,493** |

**关键结论：花的钱几乎全在蒸馏，而蒸馏的输入里约 89% 是同一条 system prompt 的重复。**

```
7,046,965 tok ÷ 3,123 次 ≈ 2,257 tok/次
其中 system prompt（buildSystemPrompt 的输出）≈ 2,000 tok
→ 每次调用有 ~89% 的输入 token 用来重复发送同一段系统提示
```

这就是省钱的总开关：**减少调用次数 = 直接砍掉这部分重复**，同时尽量让这部分走缓存命中价。

## 四个省钱杠杆（按性价比排序）

### 1. 提高 `--max-candidates`（本管道最直接的杠杆）
`gen-sft-data.js --max-candidates N`：一个剧本的消息被打成多少个批次。N 越大 → 调用次数越少 →
重复的 system prompt 越少。代码上限目前是 30（`Math.min(30, ...)`）。

> ⚠️ 但别为了省钱把 N 提到远高于**生产实际批大小**：训练样本的批形态必须贴近生产
> （`extract.ts` 每次实际发多少候选），否则学生模型会训到分布外去。改 N 之前先确认生产批大小。

### 2. 吃满 DeepSeek 上下文缓存（命中价差约一个数量级）
`train/lib/teacher.ts` 现在会统计 `prompt_cache_hit_tokens` 并打印命中率与费用估算：

```
调用 3123 次（失败 0），输入 7046965 tok（缓存命中 6100000 / 86.6%） + 输出 728493 tok ≈ ¥...
```

- 命中的前提是**前缀逐字节稳定** —— 本管道已经满足（`PROMPT_VERSION` 锁死 system prompt）。
- 若命中率明显偏低：把 `--concurrency` 调到 1~2（同前缀连续请求更容易命中），
  或缩短两次跑批之间的间隔（缓存有 TTL）。**先看命中率再动别的。**

### 3. 负样本不要花教师钱
`near_miss` / 部分 `chat` 剧本的正确标签就是 `{"events": []}`，可以让规则直接产出、不调教师
（当前 24% 的负例里有一部分是这类）。改完必须过 `gen-sft-data` 的质量门，防止把真事件当负例。

### 4. GPU 侧（不是 API 钱，是时间/电费）
- 数据够大时 **1 epoch 就够**（v3：2,715 对 × 1 epoch ≈ 170 步 ≈ 5 小时；
  对比 v1：358 对 × 3 epoch = 1,074 次样本更新，v3 一次遍历已有 2,715 次）。
- `--drop-over-seq` 丢掉超长样本，避免为几个样本把整批序列拉长。
- `--save-steps 25` + 任务计划托管 + `--resume`：中断不重跑（实测两次长训练被杀，
  一次损失 120/126 步 ≈ 3.5 小时电费）。

## 跑批前的花钱自检

```powershell
# 1) 先看要花多少：只构建 prompt 不调 API
node train\dist\train\gen-sft-data.js --out sft-probe.jsonl --dryrun
# 2) 小步试：只跑 20 个剧本，看单例成本与命中率
node train\dist\train\gen-sft-data.js --out sft-probe.jsonl --limit 20
# 3) 确认单价假设（元/百万 token）与官方一致，再看估算是否可信
$env:TEACHER_PRICE_HIT='0.5'; $env:TEACHER_PRICE_MISS='2'; $env:TEACHER_PRICE_OUT='8'
```

> 铁律不变：**教师数据一旦产出就复用**（增量蒸馏 `--out` 指向已有文件会自动跳过已完成的
> `scenario#batch`）。重复蒸馏同一批剧本 = 纯浪费。
