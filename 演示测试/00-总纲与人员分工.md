# ClassRep 演示测试 · 总纲与人员分工

> 面向：1 名主持（你）+ 4 名发消息的工作人员
> 目标：用**真实 QQ 群消息**把「AI课代表」的功能一条条演出来，并当场留下可复现的证据
> 配套文件：`01-话术库（可直接复制）.md`、`02~05-角色任务卡`、`06-主持人手册.md`

---

## 1. 一句话讲清楚我们在干什么

四个人的手机是四支"信号枪"：每人在**规定的时间点**往测试群发**规定的话**，
页面上就应该出现**规定的结果**。谁在什么时候发什么、该看到什么，全部写在各自的任务卡里。

**这不是自由聊天。** 差 30 秒、差一个字，触发到的可能是另一条流水线分支（详见 §4）。

## 2. 人员分工总表

| 角色 | 定位 | 负责的功能点 | 发消息风格 |
|---|---|---|---|
| **A · 通知主力** | 群里的老师 / 课代表 | 六类事件提取、类型配色、危机等级、待办 / DDL、查看来源 | 规整、信息全，一条一个事项 |
| **B · 闲聊干扰** | 群里的气氛组 | 规则过滤、Jev 快判（"确定不是通知"直接丢）、上下文不污染 | 刷屏式，短句、表情、附和连发 |
| **C · 变更通知** | 群里的班长 | 改期 / 换教室 / 改截止、取消、变更记录、通知与取消不相邻 | 一句话改一个字段，逐条递进 |
| **D · 边界与 @** | 群里的刺头 / 测试员 | `@` 规则、幂等去重、超长消息、一批多条、口语化时间、手机端 | 故意制造不好处理的输入 |

**为什么是这四个角色**：A 产出的"干净数据"是 B/C/D 的对照基准——没有 A 的原文，
改期、取消、去重、`@` 规则都无从演起。**A 必须先发，其他人后发。**

## 3. 演示前的 5 分钟准备（主持 + 全员）

| # | 动作 | 在哪儿做 | 通过标准 |
|---|---|---|---|
| 1 | 启动：双击桌面「ClassRep 启动（正式版）」 | 演示机 | 浏览器自动打开看板 |
| 2 | 看页头四个状态灯 | 看板顶部 | QQ / 数据库 / AI / Jev 全绿；有黄条先点掉（见 §7） |
| 3 | 确认群监听范围 | 顶栏「群管理」 | 只开**测试群**（可存成预设「演示群」），其余全关 |
| 4 | 清场 | 「演示」页 | 点「清空演示数据」，保证从零开始 |
| 5 | 导入课表（要演课表功能才需要） | 「设置」→ 课表 | ① 电脑连着校园网 → 学号一键拉取；② 拖入教务系统导出的 xls（浏览器本地解析，不上传） |

| 7 | 手机端就位 | 闲鱼……不，「今日」页二维码 / 局域网地址 | 评委能扫码看手机版（局域网访问**只读**，「刷新」按钮会自动隐藏，这是设计如此） |
| 8 | 约定内部用语 | 群外 | 见 §7「内部暗号」 |

> ⚠️ **只允许一个 QQ 客户端在线**：ClassRep 靠 NapCat 注入本机 QQ，如果这个号在

> 演示期间，工作人员都用**自己的号**发消息，不要动演示机那个号。

## 4. 三条铁律（发消息的节奏，比内容更重要）

### 铁律 1：一条"有信息量"的消息后面，**等 3 秒再发下一条**

后端不是来一条处理一条，而是**攒一批**再交给 AI：

- 群里出现一条"像通知"的消息后，**群里安静 3 秒**就开始处理（最多等 10 秒）；
- 如果 3 秒内又有人说话，它会再等——等上下文更完整。

所以：**连着快速刷 10 条通知，页面不会更快，只会一起慢。**
正确姿势是"发一句 → 停 3~5 秒 → 发下一句"。

### 铁律 2：短消息和闲聊**不会**变成日程，这是功能不是 bug

- 少于 4 个字、又没有数字或时间词的（"嗯嗯""好的""哈哈""+1"）→ 规则层直接丢；
- 长一点但确实没信息量的（"第三章我一点没看"）→ Jev 快判丢；
- 被丢掉的条数会**累加在「演示」页的统计卡**上——"累计过滤 N 条"，这就是证据。

### 铁律 3：`@` 只指向别人 = 与"我"无关，会被整条忽略

- 不 @ 任何人 → 视为全校通知，**照常处理**；
- `@全体成员` 或 `@了演示机那个号` → **照常处理**；
- **只 @ 了张三** → 直接跳过，连数据库都不进。

## 5. 一张表：功能 → 谁演 → 期待看到什么

| 要展示的功能 | 谁演 | 页面上的证据 |
|---|---|---|
| 六类事件（考试/作业/会议/活动/通知/其他）与配色 | A | 今日页卡片颜色不同 |
| 危机等级（低/中/高/紧急，类型定色相、等级定深浅） | A | 卡片右上角等级角标 + 深浅差异 |
| 待办（没时间的事项）+ 补截止后自动离开待办 | A | 今日页「待办」框 → 补了 DDL 后进日历 |
| 规则过滤 | B | 「演示」页「累计过滤」上涨 |
| Jev 快判（真闲聊不烧 AI） | B | 「Jev 快判过滤」上涨，AI 调用数不涨 |
| 改期（同一事件更新，不新增） | C | 卡片出现「已按最新通知更新」 |
| 变更记录（~~旧值~~ → 新值） | C | 详情抽屉「变更记录」 |
| 取消 | C | 卡片状态变「已取消」；群里再发一条新通知 → 生成**新**事件 |
| `@` 规则 | D | @别人的那条**永远不出现**，@全体 / @我 的出现 |
| 幂等去重 | D | 同一条原文发两遍，库里仍只有一条 |
| 一批多条 / 超长消息不阻塞 | D | 同一批里两条通知都成事件；超长消息不卡后续 |
| 口语化相对时间（"明晚八点"） | D | 时间换算正确 |
| 课表联动（"下节课"落到教室） | D | 时间和教室 = 课表里那门课的教室 |
| 课表周数 / 网格形态 | 主持 | 本周页标题「第 N 周」，切「按课表」 |
| 刷新 1/7/30 天 | 主持 | 选天数 → 「整理中 N」→ 归零 |
| 群管理：搜索、一键全开/全关、预设、撤销 | 主持 | 「群管理」页 |
| 导出日历（.ics） | 主持 | 今日页「导出今日到日历」/ 本周页「导出本周」/ 抽屉「导出这一条」 |
| 手机端 | 全员 | 评委手机扫码，布局正常 |

## 6. 推荐流程（60 分钟版 / 90 分钟完整版）

| 序号 | 环节 | 谁 | 时长 | 说明 |
|---|---|---|---|---|
| 1 | 开场：产品痛点 + 现场群聊截图 | 主持 | 3' | "你们有多少个 QQ 群？漏过通知吗" |
| 2 | 从零开始：清空 → 展示空看板 | 主持 | 2' | 制造"接下来全是现场真实产生的"的对比 |
| 3 | **第一幕：从乱到清** | A 发通知 + B 刷闲聊 | 8' | 页面从空 → 出现今日待办，颜色成体系 |
| 4 | 逐条点开：详情 + 查看来源 + 分级 | 主持 | 4' | 高亮原始群消息，讲 AI 依据 |
| 5 | **第二幕：改期不新增**（最有冲击力） | C 发改期 | 4' | 同一张卡从旧时间 → 新时间 |
| 6 | **第三幕：取消 + 重新安排** | C 发取消 | 3' | 状态变化 + 新通知生成新事件 |
| 7 | **第四幕：@ 规则与去重**（技术亮点） | D | 4' | 解释"为什么不做全量分析" |
| 8 | 待办：加一条手动待办、打勾 | 主持 + A | 3' | |
| 9 | 课表：本周网格 + "下节课" | D + 主持 | 4' | |
| 10 | 导出 .ics 到手机日历 | 主持 | 3' | 手机日历里出现，时间地点正确 |
| 11 | 隐私叙事 + 架构 20 秒 + 收尾金句 | 主持 | 4' | 见 `06-主持人手册.md` |
| 12 | 答疑与自由测试 | 全员 | 10'+ | 见 `06` 的答疑话术 |

**排练建议**：至少完整走两遍。第一遍不看话术库，暴露配合问题；第二遍掐表，
把 C 的"改期"精确卡在主持人说到「现在班长在群里发了一条新通知」的那一刻。

## 7. 现场故障与救场

| 症状 | 先看哪 | 救场话术（主持人可以说） |
|---|---|---|
| 页面出现「QQ 掉线 / kicked」黄条 | 是不是有第二台设备登了同一个号 | "设备冲突，点『重新连接』，30 秒恢复——这也说明它对本机状态是诚实上报的" |
| 状态灯红色但页面能用 | `/health` | "采集端断了，历史数据照样能看，这是我们的降级设计" |
| 发出去 15 秒还没出现 | 「演示」页看「整理中 N」是否在动 | "AI 在排队，我们先用回放剧本演示下一步" → 切「演示」页回放 |
| AI 调用失败 | 网络 / Key | 切手机热点；或在「连接」页重新填 Key；或直接走 `/demo/replay` 离线回放 |
| 时间解析看起来不对 | 消息里有没有"下周X / 本周X"这种歧义词 | 改成"明天下午两点"这类明确说法当场重发一次 |
| 完全来不及解释 | —— | "这个细节我们记在测试清单里，会后给你结论" |

### 内部暗号（在群里发这些当"口令"，评委看不懂，我们自己能同步）

| 暗号 | 含义 |
|---|---|
| `#过` | 这一轮发完了，等页面刷新 |
| `#停` | 先别发，页面卡了，主持在处理 |
| `#再来` | 重发上一条 |

## 8. 验收清单（测试是否"测到位"）

照着打勾，全绿才算这一轮测试完成：

- [ ] 六类事件都至少出现过一次，且颜色互不相同
- [ ] 四种危机等级都出现过（卡片深浅肉眼可分）
- [ ] 「累计过滤」在 B 刷完之后明显上涨
- [ ] 「Jev 快判过滤」有数字，且 AI 调用数远小于消息数
- [ ] 改期：卡片显示「已按最新通知更新」，且**没有**多出一条
- [ ] 详情抽屉「变更记录」能看出 ~~旧~~ → 新
- [ ] 「查看来源」能看到那几条原始群消息（含发送者）
- [ ] 取消后状态为「已取消」；之后的新通知生成了新事件
- [ ] 只 @ 别人的消息从未出现在页面上
- [ ] 重复发同一条原文，事件仍然只有一条（第二条被识破为重复提醒，或两条来源挂同一件事）
- [ ] 补上截止时间后，事项从「待办」框进入今日列表
- [ ] 「下节课」落到了课表里那门课的教室
- [ ] 本周页显示「第 N 周」，「按课表」网格里课程是灰底
- [ ] .ics 导入手机日历，时间地点正确
- [ ] 手机浏览器打开正常，无横向滚动
- [ ] 关闭某个群后，该群新消息不再产生事件

## 9. 谁来记录

建议固定一名"记录员"（可以是第 5 人，也可以由主持兼职）：每发现一个不符合预期的点，
当场在群里或纸上写一句 `时间 + 谁发的 + 期待什么 + 实际什么`。
**演示完立刻整理成 issue 列表**——这是测试最大的产出，比演示本身更值钱。
