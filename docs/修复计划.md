# AI 课代表 修复计划

> 基于 `763d322`（main）通读代码 + 前后端两路审查。`pnpm typecheck` 通过，后端 vitest 37 文件 / 493 用例全过；下列问题均为读代码得出，标 ✅ 的已人工复核源码，其余为审查结论、修复时需先复现。

目标体验（验收标准）：

```
git clone → 双击 启动.bat → 自动准备运行环境 → 浏览器打开
→ 向导页填 DeepSeek API Key（必填）、Jev/TypeSafe API Key（可选）
→ 扫码登录 QQ → 开始使用
换号：退出登录 → 扫另一个号 → 只看到新号的数据；换回旧号 → 旧数据原样回来
```

用户机器上唯一的前置条件：Windows 10 1803+ 与 QQ 电脑版（QQ NT）。不需要装 Node、pnpm、Git（下 zip 也能用）。

## 一、数据库绑定账号（问题 1）

### 现状 ✅

- `napcat/index.ts:40` `logoutNapcat()` 只 `clearUin()`（删掉 `data/settings.json`）然后重启，库原样保留；确认弹窗文案也写着「已整理的群和日程会保留」。
- `db/index.ts` 的 11 张表都没有账号维度：groups、messages、events、event_sources、event_history、todos、level_feedback、level_rules、courses、kv、message_seen。
- 连带问题：
  - `messages.message_id` 是单列主键，而 OneBot 的 message_id 是 NapCat 本地分配的短 id。换号后新号的消息可能和旧号撞 id，被 `INSERT OR IGNORE` 或 `message_seen` 悄悄丢掉。
  - `state.ts:38` 的 `first_run = !uin && dbEmpty`：换号后库不空，所以不会再走首次引导。
  - `history.ts:42` 上线后会对库里所有 onebot 群（包括旧号的群）拉历史。
  - 内存缓存按 group_id/message_id 做 key，换号时不清：`onebot.ts` 的 groupNameCache、selfNickname，`scheduler.ts` 的 jevScores、lastTriage。
  - 前端：
    - `Week.tsx` 的 cacheRef、`usePolling` 的 data、`Pet.tsx` 的 msgs/knownIdsRef/remindedRef 跨账号保留。
    - localStorage 里的 `classrep.groupPresets`（按群号存，套用旧号预设会把新号的群全部关掉）、`skipConnect`、`takeoverNoticeShown` 都是全局键。

### 方案：每个 QQ 号一个库文件（推荐）

```
data/
  llm.json                  ← 全局：API Key（本机级，不随 QQ 号变）
  settings.json             ← 全局：{ uin } 最近登录的号（快速登录用）
  accounts/<uin>/classrep.db ← 该号的全部业务数据
```

不在每张表里加 `account_id` 列的原因：这样要改 11 张表的主键和索引，还要改约 15 个模块的全部 SQL（ingest、scheduler、reconcile、preferences、timetable、business/todos/trash/memory 路由、cleanup、state、/health）。漏一处就会串号，而且 SQLite 改主键得重建表。每号一个库把整个问题收敛到「打开哪个文件」，message_id 冲突、kv/课表/偏好串号也随之消失。

改动点：

1. `db/index.ts`：
   - `openDb(path)` 保留。新增 `switchAccount(uin)`：关旧库 → 打开 `accounts/<uin>/classrep.db` → 建表与迁移 → 通知订阅者。
   - `db` 是 `export let`，ESM 的 live binding 可以直接重新赋值，调用方不用改。
   - 新增 `onAccountSwitch(cb)` 订阅，供各模块清理缓存。
2. 登录前（还没拿到 self_id）的状态：
   - 启动时如果 `settings.json` 里有 uin，直接打开该号的库，老用户秒进日历。
   - 没有 uin 就打开一个空的内存库占位，业务接口返回空列表。
   - `onebot.ts:151` 收到 lifecycle 且 `self_id` 与当前库不一致时调 `switchAccount`。实时消息在 lifecycle 之后才会到，不需要额外缓冲。
3. 切换时统一重置：scheduler 队列与 jevScores/lastTriage、groupNameCache、selfNickname、pipeline stats、cleanup 定时器（改为按当前 db 执行）。
4. 老数据迁移（一次性）：启动时如果存在 `data/classrep.db`，而 `accounts/` 为空：
   - 有 uin：移到 `accounts/<uin>/`，连同 `-wal`、`-shm` 一起搬。
   - 没有 uin：改名为 `data/classrep.legacy.db`，并在设置页提示「可导入到当前账号」（这一项可以后做）。
5. `first_run` 改为「没有 uin 或 LLM 未配置」（配合第三节的向导），不再依赖「库是否为空」。
6. 退出登录：
   - 文案改成「退出后可换号登录；本号数据保留在本机，下次用这个号登录会自动恢复」。
   - 另加「退出并删除本号数据」的危险选项（删 `accounts/<uin>/`）。
7. `message_seen` / `messages` 主键改为 `(group_id, message_id)`（防御性，同号内群间也可能重复）。需要做一次重建表迁移；和第 11 条的 schema_version 一起做。
8. 前端：
   - `App.tsx` 用 `<Layout key={conn.uin ?? 'none'}>` 让整棵页面树在换号时重挂载，一次清掉 usePolling、Week 缓存、Pet 状态、AccountCard 的 imgFailed。
   - `usePolling` 加 `resetKey` 参数，作为兜底。
   - `groupPresets` 的键改为 `classrep.groupPresets.<uin>`；登录成功（拿到 uin）后清掉 `skipConnect`、`takeoverNoticeShown`。
9. 测试：
   - db 层：A 号写数据 → 切到 B 号，列表为空 → 切回 A 号，数据仍在。
   - 迁移测试。
   - onebot：lifecycle 换号触发 switch。
   - 前端：uin 变化触发重挂载。

## 二、真正的一键启动（问题 2）

### 现状 ✅

- 根目录的 `启动.bat` 只跑 `runtime\node.exe app\server\dist\index.js`，这是打包后的布局。仓库里既没有 `runtime/` 也没有 `app/`，所以克隆下来双击必然失败。
- 开发用的 `scripts/dev-start.bat` 依赖系统 node + pnpm，而且 `dev.mjs` 有几处问题：
  - 每次启动都会 `git pull --autostash`。
  - 会杀掉 8000–8010 端口上任意 node.exe，可能误杀别的项目。
  - 只探测 `localhost:8000/health`，后端顺延到 8001 时浏览器就不会自动打开。
  - 用 `tsx` 跑源码（dev 模式），不是生产构建。
- `paths.ts` 用「找到 启动.bat 的目录」来定位 ROOT，这一点可以继续沿用。

### 方案

`启动.bat` 保持极薄，只负责找到或准备 node，把逻辑都交给 `scripts/launcher.mjs`：

```bat
@echo off
chcp 65001 >nul
title AI 课代表（关闭此窗口即退出）
cd /d "%~dp0"
rem 1) 自带 node → 2) 系统 node ≥ 22.15 → 3) 自动下载便携版 node 到 runtime\
powershell -NoProfile -ExecutionPolicy Bypass -File "scripts\bootstrap.ps1"
if errorlevel 1 ( echo. & echo 启动失败，详情见 data\logs\launcher.log & pause & exit /b 1 )
```

`scripts/bootstrap.ps1`（普通用户权限，不弹 UAC）：

1. 按顺序找 node：`runtime\node.exe` → PATH 里 `node -v` ≥ 22.15。
2. 都没有就下载固定版本的 `node-v24.x-win-x64.zip`，解压到 `runtime\`：
   - 版本和 SHA256 写在 `scripts/versions.json` 里。
   - 先试 nodejs.org，失败回退 npmmirror.com。
   - 下载后校验 SHA256。
3. 用这个 node 执行 `scripts/launcher.mjs`，并把参数透传过去。

`scripts/launcher.mjs`：

1. 检查构建产物（`apps/server/dist/index.js`、`apps/web/dist/index.html`）是否存在，以及是否比源码新（比对 `git rev-parse HEAD` 或 lockfile 的 hash，记录在 `data/.build-stamp`）。
2. 缺失或过期时：`corepack pnpm install --frozen-lockfile` → `pnpm -r build`。corepack 随 Node 24 自带，用户不需要单独装 pnpm，见第四节。
3. 检查 `napcat/` 是否完整（随仓库提交，见第三节），缺失时给出明确提示。
4. 启动 `node apps/server/dist/index.js`。服务端自己负责端口顺延和打开浏览器；打开浏览器的时机改为以实际监听到的端口为准，不再只在「打包版」才打开。
5. 关窗口即退出。沿用 index.ts 里已有的 SIGHUP 处理和 killTree。

同时：

- `dev.mjs` 只留给开发者用，并做以下修改：
  - 去掉自动 `git pull`，改为提示「有新版本，运行 `git pull`」。
  - 只结束命令行里带 ClassRep 路径的 node 进程，不再杀端口上任意 node。
  - 健康检查轮询 8000–8010。
- `pack.mjs` 复用同一个 `启动.bat` 和 `bootstrap.ps1`，zip 里预置 `runtime\node.exe`，因此跳过下载。
- `create-shortcut.ps1` 改为指向 `启动.bat`（生产构建），不再指向 `dev.mjs --background`。
- `package.json` 加 `"engines": { "node": ">=22.15" }` 与 `"packageManager": "pnpm@<固定版本>"`。前者给 system-ca / node:sqlite 用，后者让 corepack 能确定版本。

## 三、克隆即用：NapCat 与首次配置（问题 3）

### 3.1 NapCat 运行包

现状 ✅：`/napcat/` 在 .gitignore 里，远程仓库里没有，所以克隆下来无法采集。本地这个目录 90MB，里面还混着账号数据，不能直接提交：

- `config/napcat_<uin>.json`、`onebot11_<uin>.json`（涉及 3 个 QQ 号）
- `guild1.db*`、`cache/`、`logs/`、`_loader_debug.log`（记有 uin）

另外，缺 napcat 时 `startNapcat` 照样会写配置、spawn 一个不存在的 exe，页面最后显示「QQ 版本过旧，请更新 QQ」，文案完全误导。

方案（已定）：把实测可用的 NapCat 4.18.28 直接提交进仓库，不做自动下载。

1. 瘦身：只保留 Windows x64 需要的文件，约 20MB。
   - 删掉 `native/` 下的 linux、darwin、arm64 原生库，约 70MB，单个最大 22MB。
   - 保留的文件：
     - `native/*/win32-x64` 或 `*.win32.x64.node`
     - `native/napi2native/ffmpeg.dll`
     - `napcat.mjs`、`conout-*.js`、`worker/`、`node_modules/`、`static/`、`package.json`、`qqnt.json`
     - `NapCatWinBootMain.exe`、`NapCatWinBootHook.dll`
   - 裁剪后要在真机上完整跑一遍：扫码登录、收消息、快速登录。
2. 账号数据不进 git。`.gitignore` 里的 `/napcat/` 改为：

   ```gitignore
   /napcat/config/
   /napcat/cache/
   /napcat/logs/
   /napcat/guild1.db*
   /napcat/_loader_debug.log
   /napcat/loadNapCat.js
   ```

   提交前用 `git add -n napcat` 预演一遍，确认没有任何带 QQ 号的文件。
3. 许可证：NapCatQQ 采用 GPL v3，允许再分发。
   - 附上它的 LICENSE。
   - 新增 `napcat/README.md`，写明版本 4.18.28、上游地址 `https://github.com/NapNeko/NapCatQQ`，以及我们只改了配置文件和 `loadNapCat.js`（运行时生成）。
   - 提交前人工核对一次上游仓库的 LICENSE。
4. `.gitattributes` 加上 `*.exe *.dll *.node binary`，防止 Git 做换行转换。
5. 升级规则：只在需要时升级，一次升级大约让仓库历史增加 20MB。版本号记在 `napcat/README.md`，快速登录补丁（`config.ts`）要跟着回归测试。
6. 服务端 `startNapcat()`：先检查三个必需文件（`NapCatWinBootMain.exe`、`NapCatWinBootHook.dll`、`napcat.mjs`）。缺任何一个就进入新状态 `napcat_missing`，页面提示「采集组件缺失，请重新克隆或下载完整发布包」，并且不写配置、不 spawn（现在会误报「QQ 版本过旧」）。
7. `pack.mjs` 的第 5 步照旧复制 `napcat/`，同样排除上面那些账号文件。

### 3.2 首次配置向导（前端输入 API Key）

现状 ✅：

- DeepSeek Key：只能在连接页的「AI 接入」卡片里填（`Connect.tsx:256`），设置页没有这个入口。但桌宠的提示写的是「去『设置』页填」（`Pet.tsx:72,283`）。
- Jev/TypeSafe Key：前后端都没有输入入口，只能从 `.env` 的 `TYPESAFE_API_KEY` 读（`env.ts:70`），启动时读一次，改了必须重启。而 `ENABLE_JEV` 默认是 true，首次运行时「快判」灯一定是红的。
- 保存 DeepSeek Key 时只做格式校验，就把状态直接置为 `ok`（`routes/settings.ts:25`）：填一个无效 key 也会亮绿灯。
- `pack.mjs` 会把 `.env.release`（组长私下给的 key）打进发布包，等于把 key 分发给所有下载的人。

方案：

1. 后端：
   - 把 `llm-settings.ts` 扩展为 `ai-settings.ts`，存储文件 `data/llm.json` 加上 `typesafe_api_key` 字段。
   - `jev.ts` 和 `pipeline/index.ts` 改为读运行时配置（带 version，热更新），不再读 `env` 常量。
   - 接口：
     - `GET /api/settings/ai` → `{ deepseek:{configured,key_hint,source}, jev:{configured,key_hint,source,enabled} }`
     - `PUT /api/settings/ai`，Jev key 可以传空串表示清除。
     - `POST /api/settings/ai/test`：DeepSeek 调一次 `GET /models`，Jev 发一次最小请求，用真实结果决定灯的颜色。
   - Jev 没配 key 时灯显示灰色「未启用（可选）」，不再显示红色。
   - `.env` 继续作为开发者的兜底。
2. 前端新增 `/setup` 向导（由 FirstRunGuard 在 `!ai.deepseek.configured` 时拦截），共三步：
   - 第 1 步：填 DeepSeek API Key（必填），附「如何获取」链接；点「测试并保存」时后端做真实校验。
   - 第 2 步：填 Jev API Key（可选），可以跳过，说明「填了能省 AI 调用、更快」。
   - 第 3 步：跳转到 /connect 扫码。
   - 设置页也加入同一个 AI 配置卡片，桌宠文案改为指向设置页。
3. `pack.mjs` 删掉 `.env.release` 这一步；README 中「不用输 API Key」的说法同步改掉。

## 四、让普通用户少装东西（问题 4）

| 东西 | 现在 | 改后 |
|---|---|---|
| Node.js | 开发者自己装 | `bootstrap.ps1` 下载便携版到 `runtime/`，约 30MB，只下一次，不写注册表、不弹 UAC |
| pnpm | 全局安装 | 使用 Node 自带的 corepack，`packageManager` 字段锁定版本，用户无感 |
| 依赖 / 构建 | 手动 `pnpm install` | launcher 首次自动安装和构建，之后只在代码变化时才重新构建 |
| NapCat | 手动放目录 | 随仓库提交（仅 Windows 版文件，约 20MB），克隆即有 |
| Git | 必需 | 不必需，可以下 zip |
| API Key | 改 `.env` | 网页向导 |

进一步减负（可选，二选一，推荐 A）：

- A. 普通用户走 Release zip：CI 产出的 zip 已经带上 node.exe、构建好的前后端、NapCat（许可证允许的前提下），解压即用，不需要联网装依赖，首启最快。克隆路径留给会用 git 的人。
- B. 克隆路径完全免构建：在 CI 里把 `apps/server/dist/index.js`（esbuild 单文件，不依赖 node_modules）和 `apps/web/dist/` 提交到 `release` 分支，用户克隆那个分支，只需要 node 即可。代价是分支里有构建产物。

已知风险：

- `apps/web` 依赖 `xlsx` 的地址是 `cdn.sheetjs.com` 的 tgz。在国内网络下首次安装可能失败，建议把这个 tgz vendor 到 `vendor/xlsx-0.20.3.tgz`，改用 `file:` 引用。
- esbuild 需要跑安装脚本下载原生二进制（已在 `onlyBuiltDependencies` 里放行）。要为 npm registry 配 `npmmirror` 回退，可在 launcher 里检测到失败后重试。

### P3 体验 / 无障碍

- 桌宠：
  - 提示让用户「去设置页填 Key」，但设置页没有入口（3.2 一并修）。
  - `pet-chat.ts:126` 的「先用普通模式聊天吧」指向已删除的功能。
  - 超时错误判断没考虑 `TimeoutError`。
  - 发给 LLM 的 history 夹带「…」占位和报错文案。
  - 睡觉/问候判断用浏览器本地时区，其他地方都用上海时间。
- 连接页：
  - 文案写「扫码后会自动跳转」，实际不会。
  - `getLlmSettings` 失败时静默进入编辑态。
  - 非 Windows 上「重启采集端」按钮点了没反应。
- 状态灯：一次请求失败，4 个灯就全红；读不到数据时 Jev 灯显示「已关闭」，应显示「未知」。
- 无障碍：
  - ConfirmDialog、EventDrawer、接管弹窗：没有焦点陷阱，关闭后焦点不返回触发元素，接管弹窗不支持 Esc。
  - Toast：「撤销」按钮 6 秒消失，悬停或聚焦时应暂停计时；错误类 toast 应改为 `role="alert"`。
  - 桌宠无法用键盘操作。
  - 扫码状态变化没有 live region，读屏用户听不到。
- 轮询：标签页隐藏时照常轮询；`getToday`、`getTimetable` 被多个组件重复拉取。可以在 `document.hidden` 时暂停，或把共享数据放进 context。
- 隐私：头像从 `qlogo.cn` 加载，会把 QQ 号发给第三方，需要在界面上说明。
