# 首次启动与环境依赖


## 普通 Windows 用户需要什么

| 项目 | 来源与边界 |
| --- | --- |
| 系统 | 当前支持 Windows 10/11 x64；微信读取使用 Windows 进程接口及系统 bcrypt.dll。Linux/Docker 不提供这套微信读取能力。 |
| Git | 执行 git clone 时需要；下载源码 ZIP 可绕过克隆工具，运行本身不要求 Git。开发更新流程另需 Git。 |
| Node | 启动.bat 可下载便携 Node 24.19.0；已有 Node 至少 22.16，并须具备实际使用的 SQLite 属性。不能只检查 node:sqlite 能否导入。 |
| pnpm | 锁定 10.34.5，启动器可准备到项目内；构建子进程也必须能找到所选 Node 和 pnpm，不能暗中依赖全局安装。 |
| 网络与磁盘 | 首次需要下载 Node、pnpm/npm 依赖、Python/pip 包及可选 NapCat；下载失败、代理、证书拦截、磁盘权限均需按报错判断。解压目录必须可写。 |
| Python | 微信固定使用项目内 classrep-fastjudge/py/python.exe，启动器准备 3.12.10 x64 便携运行时及 requirements.txt。生产解压用锁定的 zstandard 包，不需要开发测试专用 Zstd DLL。 |
| QQ | 用户自行安装 QQ NT，通过本机登录；NapCat 固定版本可自动下载并验证。QQ 安装发现依赖注册表或常见安装位置，便携/非标准安装须检查具体报错。 |
| 微信 | 用户自行安装并登录受支持客户端。目前仅有 4.1.15.50 特定 Weixin.dll 构建证据；相同版本号不保证相同模块。需明确选择存储目录和群。 |
| AI | 用户自己的 OpenAI 兼容接口、模型及 Key；仓库不携带可用凭证。无 Key 可启动界面，AI 整理和助手不可用。 |

Node 依赖使用内置 SQLite，正常安装不要求本地编译 SQLite；发布的 Python wheel 是否能下载和导入仍取决于系统架构及网络。不能把“本机有缓存时安装通过”当作新电脑已验证。

## 已证实的可移植性问题

- 已发布启动器只定位 Node 可执行文件，没有为后续脚本正确提供 Node/pnpm 的命令搜索路径。缺少全局工具时，依赖安装或构建里的 `node`、嵌套 `pnpm` 命令可失败。本轮修复在项目运行环境提供可执行入口，不修改系统 PATH。
- 原最低版本写为 Node 22.15，探针只导入 SQLite；代码已使用 22.16 才提供的 `DatabaseSync.isTransaction`。本轮统一最低版本并验证实际 API。
- 原 Windows 启动在 Python 准备失败后直接退出，无法进入页面检查其他功能。本轮改为明确报告受影响能力并继续启动；不会把不完整运行时宣称为就绪。
- 原微信同版本不同构建及依赖失败可能落为笼统的连接失败。本轮分类提示，不将所有失败都归因于版本，也不解除未经验证的模块限制。

## 微信旧版本边界

当前不是官方跨版本连接 API。身份和数据定位包含已验证模块指纹、静态结构与 4.x 数据库加密格式的假设。旧 3.x 的进程、模块和存储格式不同，4.x 其他构建的偏移及结构也不能直接沿用。移除版本判断可能读错地址或误认数据，因此需要针对目标构建增加适配及回归证据。不要通过降级客户端试错；先取得完整版本号、实际错误码和连接阶段。

## 数据、端口与本地状态

- `.env`、账号数据、聊天数据库和登录授权均不随仓库分发。不要复制他人的配置或数据目录来补依赖。
- 8000 被占用时会尝试后续端口；仅复用安装身份匹配的现有服务，不应杀掉其他安装。
- 浏览器存储按来源隔离。新代码额外按安装身份和账号隔离微信目录记忆，目录记忆不代表读取许可。
- 数据库启动时执行迁移；已有数据迁移与备份失败需看具体报错，不能清空用户数据来证明启动成功。
- `NODE_MIRROR`、`PNPM_MIRROR`、`PYTHON_MIRROR`、`NAPCAT_MIRROR` 等启动下载配置属于启动进程环境；服务端 `.env` 配置并不等于启动脚本已读入这些变量。

## 验证边界

自动测试使用合成消息、临时数据库和无凭据启动；不能替代另一台 Windows 电脑的真实登录与采集验收。请提供系统架构、Node/微信构建版本和脱敏错误分类定位问题。禁止通过关闭身份、路径或版本检查绕过失败。

安装目录必须完整：缺少启动.bat 时立即报安装不完整，不向上寻找其他安装的数据目录。
