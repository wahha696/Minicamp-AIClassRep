# ClassRep 本地快判 · 基座与标签定义 v1

> 决策方：本地模型训练侧（box / CPU）  
> 日期：2026-09-28  
> 约束：无 NVIDIA、无 torch、约 15G 内存 8 核；合成用 `DEEPSEEK_API_KEY`

## 1. 目标接口（对齐现有 `jev.ts`）

本地快判输出与 TypeSafe Jev **同形态**：对过滤后的每条候选消息给出 `score ∈ [0,1]`，语义为：

> 「结合上下文，该条消息是否提供可能影响学生日程或待办的具体信息」的概率。

调度阈值暂时沿用现网（可校准后改）：

| 阈值 | 含义 |
|------|------|
| `score < 0.2`（`JEV_DROP_BELOW`） | 丢弃，不送 LLM |
| `0.2 ≤ score < 0.8` | 不确定，攒批后送 LLM |
| `score ≥ 0.8`（`JEV_URGENT_AT`） | 高优先，安静后尽快送 LLM |

**不替代 LLM 提取**（标题/时间/地点/改期对象仍由 LLM 做）。

## 2. 标签定义（硬标签）

单样本一条「待判定消息」+ 可选上下文（此前最多 10 条非噪声）。

### `label` ∈ {0, 1}

| 值 | 名称 | 正例 / 反例口径（与 FR-4.1 / `jev.ts` criteria 一致） |
|----|------|------------------------------------------------------|
| **1** | `schedule_signal` | 考试、作业、会议、活动、通知的时间/地点/要求，或其改期、取消、补充、确认；**已说定具体时间或日期**的聚餐、吃饭、出游、打球等约定；零碎但可与上下文拼成上述信息的片段 |
| **0** | `noise_or_chatter` | 纯闲聊、寒暄、表情、无关讨论；**没有说定时间**的随口提议/询问（如「晚上约饭吗」「有人开黑吗」） |

### 可选软标签 `soft_label` ∈ [0, 1]

由 DeepSeek 教师按同一指令打分（或多数票），用于概率校准与蒸馏；评测主指标仍看硬标签召回（**误丢通知代价 ≫ 多调一次 LLM**）。

### 样本 schema（给产品经理脚手架）

```json
{
  "id": "string",
  "group_name": "string",
  "context": [{ "sender_name": "string", "text": "string" }],
  "message": { "sender_name": "string", "text": "string" },
  "label": 0,
  "soft_label": 0.12,
  "source": "synth | mock | human",
  "scenario": "optional-剧本或主题名",
  "notes": "optional"
}
```

建议首批规模：合成 **3k–8k**（正负约 1:2～1:3，正例略少但覆盖改期/取消/短变更保活词）；评测集 **300–500** 人工抽检或与现有 `data/mock` 剧本对齐；另留 **时间分割 / 群分割** 防泄漏。

## 3. 基座选型（CPU / 无 torch）

### 主选（v1 落地）

**`jieba` 分词 + `scikit-learn`：`TfidfVectorizer`（字 2–4 gram ∪ 词 1–2 gram）+ `CalibratedClassifierCV(LogisticRegression, method='isotonic' 或 'sigmoid')`**

| 理由 | 说明 |
|------|------|
| 约束合规 | 纯 CPU，不依赖 torch / CUDA |
| 接口匹配 | `predict_proba` → 直接当 `score` |
| 资源 | 15G / 8 核绰绰有余；推理毫秒级，适合每群 ≤2s 打分 |
| 可解释 | 可导出高权重 n-gram，便于对坏例改规则/合成 |
| 工程 | 单文件 `joblib` 模型；Node 侧可用子进程或后续 ONNX 导出 |

依赖（训练环境）：`scikit-learn`、`jieba`、`joblib`、`numpy`（均可 pip，无 torch）。

### 备选（若 v1 召回不够再开）

1. **fastText supervised**（官方 C++ CLI / `fasttext` 包）：短中文极快，仍无 torch。  
2. **LightGBM + 同上 TF-IDF 稀疏特征**：非线性更强，部署稍重。  
3. **规则特征并联**：变更保活词、时间正则、作业/考试词典命中 → 与模型分数 max/融合（对齐 G1-1 噪声过滤经验）。

**明确不做（本阶段）：** 本地 LLM / GGUF / sentence-transformers（要 torch 或内存/延迟不合「快判」）。

## 4. 训练方案摘要（供脚手架对齐）

1. **合成**：DeepSeek 按班级群话术生成 `(context, message, label)`，覆盖：考试/作业 DDL、改期取消、短变更（「取消了」「改线上」）、定了时间的聚餐、闲聊、约饭询问、表情刷屏。  
2. **教师打分**：对合成+mock 再跑一遍软标签，筛掉自相矛盾样本。  
3. **训练**：硬标签为主损失；可用 `soft_label` 做 soft-target 或仅作校准集。  
4. **验收**（对齐 `jev-calibrate.ts` 精神）：在固定评测集上 **正例召回 @0.2 ≥ 现网目标（争取 100% / 不低于 mock 剧本）**；负例丢弃率尽量高；报告 `@0.8` 的精确率。  
5. **导出**：`models/local-jev-v1.joblib` + `metrics.json`；推理脚本签名对齐 `scoreWithJev(candidates, context, groupName) -> number[]`。
