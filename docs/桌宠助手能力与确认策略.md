# 桌宠应用助手

助手使用用户在 AI 接入中保存的接口、模型和密钥。模型只提出受控操作方案；实际操作复用应用现有路由的校验、账号代次和业务规则。服务端注册表为 `apps/server/src/assistant/registry.ts`，客户端可通过 `GET /api/assistant/capabilities` 获取完整字段 schema 与策略。

## 能力清单

| 应用功能 | 助手能力 | 执行方式 |
| --- | --- | --- |
| 日程、今日与待办查询 | `events.list`、`events.read`、`todos.list` | 只读；详情保留原消息来源 |
| 事项完成、恢复、取消、时间地点标题和重要性调整、解除人工保护 | `events.update` | 显示精确对象与参数，确认后通过原 API 修改；要求版本与更新时间 |
| 接受或拒绝 AI 提议的事项修改 | `events.proposal` | 确认后执行原冲突检查 |
| 手动待办新增、编辑和完成 | `todos.create`、`todos.update` | 确认后执行 |
| 群列表、课程名称、启用采集 | `groups.list`、`groups.update` | 修改须确认；微信仍须已有有效连接和授权范围 |
| 重新整理群通知 | `groups.retry` | 标明会调用用户配置的 AI；确认后提交后台，回执不声称整理已完成 |
| 删除某群的数据 | `groups.clear` | 破坏性确认，遵循原 API 去重与来源保留逻辑 |
| 长期偏好查看、新建、修改和删除 | `memory.list/create/update/delete` | 保存与修改须确认；仅当前空间生效 |
| 自动总结的重要性偏好 | `settings.memory/read/delete/clear` | 查看只读；开关、删除、清空分别确认 |
| 手机提醒规则 | `settings.reminders/read` | 可修改时间及次数；渠道尚未验证，不能开启外发 |
| 局域网分享开关和旧链接失效 | `settings.lan`、`settings.lan.rotate` | 明确外部访问影响后确认 |
| 回收站 | `trash.list/restore` | 只读或确认恢复 |
| 课表查询、课程规则和学期/节次编辑 | `timetable.read/edit` | 预览确认；保留未修改课程和来源；revision 防覆盖 |
| 单次停课、调课、补课与撤销调整 | `timetable.exception` | 确认后执行原课表冲突校验 |
| 单次课程完成与撤销 | `timetable.occurrences/complete` | 查询明确日期的真实课次，预览课名、日期和时间后确认；与周历手动按钮共用 API |
| 课表历史版本及恢复、清空 | `timetable.versions/restore/clear` | 查询只读，恢复/清空为破坏性确认 |
| QQ、微信历史补全 | `history.status/sync/cancel/retry` | 启动/续传明确读取及 AI 影响，确认后创建或复用服务器任务；取消安全停止，持续进度在连接页 |
| 空间改名 | `workspace.rename` | 确认后修改当前空间 |
| 课表文件和教务导入 | `timetable.import` | 提供设置页入口，用户选文件/输入登录信息并核对预览；不声称已导入 |
| 备份下载和日历导出 | `data.backup`、`events.export` | 固定应用下载链接，由用户点击并由浏览器保存 |
| 备份恢复、清空整个空间及旧账号管理 | `data.restore/reset`、`workspace.manage` | 引导到真实设置页的确认流程；涉及整库和身份的操作在专门页面核对完整范围并确认 |
| QQ/微信登录、退出、修复和微信目录选群 | `connections.manage`、`wechat.selection` | 引导连接页；用户本人完成登录、操作系统权限和明确读取范围 |
| AI 接口、模型和密钥 | `settings.ai` | 引导 AI 接入卡；助手不读取、代填或回显密钥 |
| 桌宠形象、说话风格和本地显示 | `settings.pet` | 确认后通过固定浏览器动作修改；宠物外观在本浏览器所有空间共用；上传图片仍须本人选择文件 |
| 演示、重放、文本导入 | `demo.manage` | 引导演示页选择明确样本/文本和 AI 外发范围；演示未开启时页面会说明 |

“完成某门课”支持标记具体日期的一次课程完成或撤销，未来重复课次不受影响；对应作业或事项完成仍使用事项 API。服务器提供上海时区当前日期以及最近三周的课次资料；更远日期通过有界查询工具取得真实标识。同名多课次、日期不明确时应先追问，不能猜测或把整学期标为完成。确认卡显示服务器查得的课名、具体日期与时间。

完成状态存于当前空间的 `course_completions`，绑定学期起点、课次 ID、课名与起止时间。调课、停课、改时间或改课名不会把旧标记套到新课次；改教师或教室可保留。清空课表只使历史记录不再显示，恢复相同课次的版本可恢复显示原标记。完整数据重置会删除这些记录；整库备份和恢复包含它们。旧空间合并遇到同课次完成状态冲突时以主库为准，原库和迁移快照保留供恢复。

## 安全及状态约束

- 注册表拒绝未知工具、额外字段、任意 URL、SQL、shell、文件路径和密钥参数。AI 不拥有确认工具。
- 所有模型写操作都必须在应用中点击确认。用户历史、群内容、长期记忆和自定义人设作为资料传入，不能覆盖确认要求。
- 方案绑定随机 HttpOnly 会话、当前空间及账号代次，15 分钟后过期。切换空间、取消、更新方案或服务重启均使旧方案失效。
- 同一方案确认时原子消费；双击不能重复执行。完成回执缓存 15 分钟，同会话断线重试可找回结果。服务重启后不自动重放未确定的操作，应核对应用现状再提新请求。
- 多操作不冒充数据库原子事务：发生失败立即停止后续操作，并逐项列出成功、失败和未执行；不自动重复已成功操作。
- 助手模型上下文只提供有限数量的事项/课程/群元数据和已启用偏好，不附带原始聊天、密钥、操作系统路径或备份内容。列表超出上下文范围时应使用查询工具，不猜测对象 ID。
- `exclude_calendar` 规则须指定课程与事项类型，仅影响后续绑定到该课程的群里匹配类型的新日程候选；来源保留可查。`note` 是一般回答倾向，不自动执行动作。没有内置“物理作业不提交”等个人规则。

## 验证

`pnpm --filter server exec vitest run src/routes/assistant.test.ts` 使用注入的模拟 LLM 与脱敏对象，验证未知工具拒绝、会话/空间隔离、过期与取消、并发确认幂等、断线回执找回、部分失败停止、来源信息不外发、课表合并保留和长任务提交语义。测试不调用真实 AI，也不读取用户聊天数据库。

## 尚未支持自动执行的能力

不能将上表概括为“所有操作都可执行”。文件上传、教务登录、QQ/微信登录及授权、目录与群范围选择、整库恢复和清空、AI 凭证输入、自定义形象文件、演示输入仍需用户在实际页面完成，助手只提供入口。下载备份/ICS 由浏览器处理，不是助手读取文件。

以下能力没有执行工具：向真实联系人发消息、开启尚未验收的自动手机推送、任意系统命令/SQL/文件访问、自动安装或降级微信、给整学期重复课表规则标记永久“已完成”。长期自动过滤目前只支持明确课程绑定加事项类型的未来新日程排除，其他自由文字偏好仅作为回答参考，不能宣称已改变处理流水线。
