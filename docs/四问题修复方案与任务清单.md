## 问题 1：数据库没有跟账号绑定，切换账号后旧数据仍保留

### 1.1 根因分析

本项目里的「账号」= 采集端（NapCat）登录的 QQ 号 `uin`，全链路现状：

1. **账号只是一个文件里的一个字段**：登录成功后 `apps/server/src/napcat/onebot.ts:150-157` 从 OneBot `lifecycle` 事件拿到 `self_id`，写入 `data/settings.json` 的 `{ uin }`（`napcat/manager.ts` 的 `setUin/getUin/clearUin`）。
2. **退出登录不碰数据**：`apps/server/src/routes/connect.ts:40-47` 的 `POST /api/connect/logout` 只调 `logoutNapcat()`（忘掉 QQ 号 + 重启采集端回到扫码），代码注释原文就是「**数据保留**」。
3. **库是全局单库、无账号维度**：`apps/server/src/db/index.ts` 打开唯一的 `data/classrep.db`，全部业务表（`groups / messages / events / event_sources / event_history / todos / level_feedback / level_rules / courses / kv / message_seen`）以 `group_id` 或自增 id 为主键，**schema 里没有任何 `owner_uin`/账号字段**。

结论：数据的归属是「这台电脑」而不是「这个 QQ 账号」。换号登录后，旧账号的群监听、事件、待办、课表、记忆规则全部原样可见，甚至旧账号的 `groups` 监听配置会被流水线用来处理新账号收到的消息——既是隔离缺陷，也直接污染 AI 提取结果。

### 1.2 技术方案（推荐：按账号分库）

**方案 A：按账号分库（推荐）** —— `data/classrep.db` → `data/accounts/<uin>/classrep.db`

- 换号 = 切换库文件目录，天然物理隔离；删除某账号数据 = 删除其目录；备份/导出 = 拷目录。
- **查询代码几乎零改动**：`db/index.ts` 现成的 `openDb(path)` 已经支持重复调用（先 close 旧连接再开新的，见 147 行；测试用 `openDb(':memory:')` 就是这个机制）。ESM `export let db` 是活绑定，所有 `import { db }` 的模块自动跟随切换。
- 新增 `switchAccount(uin)`：
  1. 静默流水线（停 `startScheduler` 的在途批次、等待 in-flight 提取任务结束；NapCat 断连后消息流天然静止，但要显式等待）；
  2. `openDb(join(ACCOUNTS_DIR, uin, 'classrep.db'))` —— 幂等建表 + migrate 已内置；
  3. 更新 `getConnectStatus()` 的 `dbEmpty` 判定来源（首个账号引导 `first_run`）。
- **挂载点**：登录成功的唯一信号是 lifecycle 的 `self_id`（`napcat/onebot.ts:150` 附近现调 `setUin(uin)` 处），在其后追加 `switchAccount(uin)`；登出路径在 `logoutNapcat()` 里先静默流水线再切回「无账号」态。
- **旧数据迁移**（一次性）：启动时若存在旧 `data/classrep.db` 且 `settings.json` 有 `uin` → 将其移动到 `data/accounts/<uin>/classrep.db`；无 `uin` 则移入 `data/accounts/legacy/`，前端提示一次。
- 归属决策：`kv`（semester_start / memory_enabled）、`courses`（课表）、`todos` 等全部随账号库走（每个班级账号自己的学期与课表）；`data/llm.json`（API Key）保持机器级共享，也可顺带挪进账号目录（一行改动，建议先保持共享）。

**方案 B（否决，记录原因）**：给所有表加 `owner_uin` 列并改写全部查询/主键/索引 —— 15 张表、几十处 SQL、大量测试需回归，改动面与风险远高于方案 A，且无法获得「删目录即删账号」的运维便利。

### 1.3 代码改动模块

| 模块 | 改动 |
|---|---|
| `apps/server/src/db/index.ts` | `openDb()` 支持按账号路径打开（现成能力）；新增 `ACCOUNTS_DIR` 解析 |
| 新增 `apps/server/src/accounts.ts` | `currentUin()` / `switchAccount(uin)` / `closeCurrentAccount()` / 旧库迁移 |
| `apps/server/src/napcat/onebot.ts` | lifecycle 拿到 `self_id` 后调用 `switchAccount(uin)` |
| `apps/server/src/napcat/index.ts` | `logoutNapcat()` 增加静默流水线 + 关闭当前库 |
| `apps/server/src/paths.ts` | 增加 `ACCOUNTS_DIR = data/accounts` |
| `apps/server/src/pipeline/scheduler.ts`、`jobs/cleanup.ts` | 提供可暂停/恢复钩子（切库前 quiesce） |
| `apps/web/src/pages/Connect.tsx` | 退出登录确认文案改为「该账号的数据将保留在本机，换号登录互不可见」 |
| `apps/server/src/db/db.test.ts` 等测试 | 补「切号 → 数据隔离 → 切回 → 数据还在」用例 |

## 问题 2：原始启动代码无法一键启动

### 2.1 根因分析

1. **仓库根的 `启动.bat` 是「打包版」入口**：内容为 `"runtime\node.exe" "app\server\dist\index.js"` —— `runtime/` 与 `app/` 目录只在 `scripts/pack.mjs` 产出的 `release/ClassRep/` 里存在，克隆仓库后双击必然闪退。
2. **真正的开发启动链路依赖过多**：`pnpm start` → `scripts/dev.mjs`，硬性要求：Node ≥ 22.13（`node:sqlite`）、pnpm 在 PATH、已执行过 `pnpm install`、`napcat/` 运行包已手工放置。dev.mjs 没有对其中任何一项做安装/兜底，第 2 步 `pnpm --filter web build` 直接报错退出。
3. **每次启动全量重打包前端**（dev.mjs 第 2 步无条件 `vite build`），启动慢且放大了依赖缺失问题。
4. **找不到 QQ / 缺 NapCat / 缺 Key 时只报状态不给出路**，非开发者无法自助。

### 2.2 技术方案：启动入口「环境自适应」

改造 `启动.bat` 为唯一入口，运行时自检并补齐环境，两条路径：

- **打包布局**（存在 `app\server\dist\index.js`）→ 维持现状直接跑；
- **仓库布局**（存在 `apps/`）→ 调 `node scripts/bootstrap.mjs`，bootstrap 负责：
  1. **确保 Node**：优先用 PATH 里的 node（校验 `node:sqlite` 可用，即 ≥22.13）；没有则由 `.bat` 内联 PowerShell 下载官方 win-x64 `node.exe` 到 `runtime/`（版本钉 v24 LTS，逻辑从 `pack.mjs:60-78` 抽成 `scripts/lib/fetch-node.mjs` 复用）。`.bat` 本身不依赖预装 Node —— 这是「双击就能跑」的关键。
  2. **确保包管理器与依赖**：`package.json` 增加 `"packageManager": "pnpm@10.x"`，用 Node 自带 corepack 启用 pnpm（用户无需装 pnpm），`pnpm install --frozen-lockfile`；失败时中文报错。
  3. **确保 NapCat**：缺 `napcat/NapCatWinBootMain.exe` 时走问题 3 的自动下载（见下），不让用户手工找包。
  4. **确保构建产物**：`apps/web/dist`、server 产物缺失或源码哈希变化才重新构建（给 dev.mjs 的重打包加缓存判断）。
  5. 复用 dev.mjs 现成的「杀旧后端 / 起后端 / 轮询 /health / 开浏览器」，把它拆成 `scripts/lib/start-server.mjs` 供两条链路共用。

验收口径：**在一台只装了 Windows 10/11 + QQNT 的电脑上，`git clone` → 双击 `启动.bat` → 浏览器自动打开**，全程无手工命令行。

### 2.3 代码改动模块

| 模块 | 改动 |
|---|---|
| `启动.bat` | 重写为布局探测 + 内联 PowerShell 兜底下载 Node |
| `scripts/bootstrap.mjs`（新） | 五步自检安装流程，幂等，支持 `--no-update` 等既有参数 |
| `scripts/dev.mjs` | 拆出 `lib/fetch-node.mjs`、`lib/start-server.mjs`，加构建缓存判断 |
| `package.json` | `"packageManager"` 字段；`start` 指向 bootstrap |
| `README.md` | 本地开发一节改为「克隆 → 双击启动.bat」 |

## 问题 3：GitHub 仓库克隆后不能直接运行（NapCat 痛点）

### 3.1 根因分析

克隆后不能跑，是三个「不进 git」叠加的结果：

1. **`/napcat/` 整目录被 gitignore**（`.gitignore:12`）：`NapCatWinBootMain.exe`、DLL、运行脚本、`node_modules` 全在本地。他人克隆后采集端直接缺失，后端 `startNapcat()` 进 error 态。README 只有一句「把 NapCat.Shell 运行包放到 napcat/ 目录」——用户根本不知道去哪下、放哪、放什么版本。这正是 NapCat 生态的已知痛点：插件/运行包不在远程仓库，克隆了也用不了。
2. **`.env` 不进 git**（正确做法），但缺省体验断裂：没有 `.env` 时 LLM 不可用。虽然连接页已支持网页存 Key 到 `data/llm.json`（`llm-settings.ts`，优先级高于 .env、保存即生效），但**前端没有「未配置 → 引导输入」的首启流程**，用户不知道要去哪里填。
3. **无 CI 无 Release**：仓库没有 GitHub Actions，「克隆可跑」没有任何自动验证；也没有预构建产物可下载，非开发者完全无法自助。

### 3.2 技术方案：目标流程「克隆 → 双击 → 扫码 → （可选）填 Key → 直接用」

分层解决，核心思路是 **运行包不进 git、首次启动时从官方源自动获取**（与 NapCat 官方分发方式对齐，规避许可证/仓库体积/杀软误报三重问题）：

1. **NapCat 自动引导（核心）**
   - 新增 `scripts/fetch-napcat.mjs`：读 `napcat.version.json`（钉死的 NapCat 版本号 + SHA-256）→ 从 NapCat 官方 GitHub Releases 下载 Shell 包 → 校验和 → 解压出 `NapCatWinBootMain.exe` 等到 `napcat/`（沿用 `pack.mjs` 的排除规则）。
   - 网络兜底：支持 `NAPCAT_MIRROR` 环境变量切换加速镜像。
   - 两个触发点：① bootstrap 首检缺文件自动拉；② 后端 `POST /api/setup/fetch-napcat`（带进度查询接口），前端在连接页 error 态（「需要先安装 QQ 电脑版」旁）显示「一键下载 NapCat 组件」按钮 + 进度条。
2. **Secret Key 前端可选输入（打通最后一公里）**
   - 能力已在：连接页「AI 接入」卡片 → `saveLlmSettings()` → `data/llm.json`，优先级高于 `.env`，保存即生效无需重启。
   - 需补首启引导：`GET /api/connect/status` 已返回 `first_run`，再联合 `getLlmSettings().configured === false`，前端在连接页/今日页顶部挂引导卡「填入 DeepSeek API Key（可选，不填也能收消息看日程，AI 整理不可用）」；填完即时消卡。
   - Jev 的 `TYPESAFE_API_KEY` 保持可选，失败已自动回落 LLM，无需强配。
3. **CI 保证「克隆可跑」持续成立**
   - `.github/workflows/ci.yml`：push/PR 跑 `typecheck + test + build`；另加 **fresh-clone 冒烟 job**（干净环境 install → build → 起后端 → `GET /health` 200）。
   - `.github/workflows/release.yml`：打 `v*` tag 自动 `pnpm pack:win`，把 `ClassRep.zip` 挂到 GitHub Release —— 这同时就是问题 4 的 T0 交付物。
4. **README 重写**：首屏只保留目标流程三步图 + 「克隆版 / 免安装版」两条路径；`napcat/` 获取方式改为「启动时自动下载，也可手动放置」。

### 3.3 代码改动模块

| 模块 | 改动 |
|---|---|
| `scripts/fetch-napcat.mjs`（新）+ `napcat.version.json`（新） | 官方包下载/校验/解压 |
| `apps/server/src/routes/` 新增 `setup.ts` | `POST /api/setup/fetch-napcat` + 进度查询；接入 `index.ts` |
| `apps/server/src/napcat/state.ts` | error 态区分「缺 QQ」与「缺 NapCat 运行包」，文案带动作 |
| `apps/web/src/pages/Connect.tsx` | 「一键下载 NapCat」按钮 + 进度；LLM 未配置引导卡 |

| `scripts/bootstrap.mjs` | 集成 fetch-napcat |
| `README.md` | 快速开始重写为目标流程 |

## 问题 4：让普通用户一键部署（思考方案）

### 4.1 方案矩阵（按用户门槛从低到高）

| 层级 | 目标人群 | 形态 | 依赖 | 状态 |
|---|---|---|---|---|
| **T0 免安装包（主推）** | 普通同学 | GitHub Releases 下载 `ClassRep.zip` → 解压 → 双击 `启动.bat` | 只要装了 QQNT，无需 Node/git | `pack:win` 已具备，缺发布与更新通道 |
| **T1 克隆即用** | 会 git 的同学 | `git clone` → 双击 `启动.bat`（问题 2+3 方案） | 无 | 本次开发 |
| **T2 Docker/云主机** | 想挂机 24h 的用户 | `docker compose up`：napcat 容器（OneBot WS 服务端）+ classrep 容器 | Docker | 架构已解耦（WS 对接 `ws://127.0.0.1:3001` 可改指容器名），扫码走网页 |
| T3 托管 SaaS | — | 不做 | — | 与「数据不出本机」定位冲突 |

### 4.2 推荐落地（T0 打磨 + T2 备选）

1. **T0 主路径 = Release 压缩包 + 应用内自更新**
   - `pack:win` 产物已经做到「无 Node、无 UAC、双击即用」，缺的只是把「发新版」自动化 + 老包能升上来：
     - `scripts/update.mjs`：启动时查 GitHub Releases `latest`，版本号更新则后台下载新 zip，替换 `app/` 与 `runtime/`，**保留 `data/`**（含账号库），失败静默沿用旧版；
   - Release 流水线（同问题 3 的 workflow）：push tag 自动构建并附 `ClassRep.zip`，Release 说明写清「下载 → 解压 → 双击」。
   - 验收：普通用户从看到仓库到用上，只做「下载 → 解压 → 双击」；已装用户升级不丢数据。
2. **T2 备选：Docker Compose（面向挂机/非 Windows 需求）**
   - `deploy/docker-compose.yml`：`napcat` 服务（官方社区镜像，挂载 QQ 配置卷，暴露 OneBot WS）+ `classrep` 服务（node:24 镜像跑 server，`ONEBOT_WS_URL` 指向 napcat 服务名）；扫码二维码已由后端透出到网页，可无头登录；
   - 这是「无 Windows 电脑 / 想部署在宿舍小主机」用户的唯一路径，作为可选附录即可，不投入过多。
3. **明确不做**：注册登录、云端多租户、托管版 —— 与隐私定位和单人本机 Demo 定位冲突。

### 4.3 代码改动模块

| 模块 | 改动 |
|---|---|
| `.github/workflows/release.yml`（新） | tag → build → pack:win → 上传 Release |
| `scripts/update.mjs`（新）+ `启动.bat` 挂钩 | 压缩包版自更新（保留 data/） |
| `deploy/docker-compose.yml`（新，P2） | napcat + classrep 双容器编排 |
| `apps/server/src/napcat/onebot.ts` / `env.ts` | WS 地址可配置（容器化前提） |
