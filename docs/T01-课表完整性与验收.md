# T01：课表完整性、冲突和安全导入

## 本次交付

- 不再将课程存储限制为五个固定块。每条重复规则有稳定 `id`、`course_id`、起止节次、星期、周次集合、可选实际时间、教师、地点、校区、班级与来源。保留 `block` 只为旧数据兼容，新的展开和渲染不依赖五块模型。
- 学期配置保存第一周周一、学期名称、学校、校区/作息方案、学期长度和逐节作息。默认 12 节作息是**示例**，导入时必须人工核对；可增至 24 节，周次支持 1–60。
- 一次具体课次由规则与校历展开，身份为规则 ID + 日期。停课/请假、单次调课、补课、暂时保留以单独日期例外保存，不修改其他周。校历和展开逻辑由前后端共用。
- `1–4`、`3–5`、`9–12`、`11–12` 保留完整范围。支持周一至周五表头、`周一`/`星期一`、转置课表、同格多课、合并的节次标签、跨行/跨列连堂。跨多个星期的课程合并格不猜测，转待确认。
- 文件的所有 sheet 都列出课程数和待确认数，用户选择；网页多张候选表也可选择。HTML 嵌套布局表不会重复计入课程，校历保留用于推算起点。
- 导入对账保留源表名、1 起算行/列、原文、处理状态、关联规则 ID 和核对备注。备注中的未定节次实践课也转待确认；没有日期/节次时不凭空安排。待确认项须手动补全或明确说明忽略理由。
- 重复导入预览新增、修改（原值与新值）、删除、保留及被保护的人工修改。默认合并；不同学期起点禁止直接合并。空导入、未处理项、无效作息/周次/例外会被后端拦截。整表减少超过 20% 或可能覆盖人工修改，需要额外确认。
- 保存、清空和恢复前，在同一数据库事务中保留快照；最近 20 个版本可恢复，恢复本身也可撤销。页面编辑冻结起始 revision，保存/恢复及带 revision 的清空防止并发覆盖。历史快照接口不开放给局域网客户端。
- 网格按实际作息逐节展示，连堂覆盖所有相关行，计数不重复。同格全部课程可见；全天列表每次课程只出现一次。详情通过点击或键盘 Enter 展开，无关键字段只在 hover 可见。
- 真实冲突按具体时间区间相交计算，单双周不误报、相邻时间不冲突。考试/安排有明确起止时才参与；DDL 单独时点不当作占课时。提示保留双方并解释重叠时间；请假、调课或保留由用户决定。

## 计数和追踪约定

“规则”不等于“实际课次”：一条每周一上课、持续 16 周的规则会展开为 16 个实际课次；同格两门课是两条规则。导入界面分别展示源片段数、规则数、待确认/明确忽略数、预计保存规则数。按周页面统计实际课次。

源片段是原表中的非空内容格，不是算法猜出的课程数；一格可能对应多条规则。未知片段不能声称已经知道其中有几门课。当前导入记录和每条规则的 `source` 提供追踪，旧批次可在恢复快照中核查。

## 如何使用

1. 设置 → 课表 → 选择文件；有多个工作表时选择目标表。也可手动创建课表。
2. 填写/核对第一周周一、学期周数、学校与校区，展开作息表校对时间。
3. 展开“导入原文与逐项对账”。对未知项从原文手动补课，在“全部课程规则”中修正字段，然后确认完整；不属于课程的内容写明理由后忽略。
4. 展开差异列表，选择合并或替换。切换预览周次，核对单双周、冲突和晚课。
5. 勾选核对确认后保存。保存后可在“编辑课程、作息与单次调课”中编辑；在“可恢复版本”中撤销。

## 边界与发布前仍需完成

- 本次不是“绝对成熟”认证。没有真实高校账号和用户原始冲突文件；需补充脱敏真实样本持续做回归，特别是非标准字段顺序、隐藏列、复杂嵌套表、学校临时校历通知。
- 作息示例不是任何学校的官方时间。当前为一个活动学期配置；不同校区/季节可调整默认方案、按规则覆盖时间或按日期录入例外，但尚无多套自动生效日期的作息模板管理器。法定假日不自动替代学校校历。
- 规则和日期例外持久化，具体课次按需确定性展开，不另建易失效的冗余 occurrence 表；`course_id` 为稳定课程身份，尚无独立的学校课程目录管理界面。
- 目前按上海时区、单日内课程处理；跨午夜课程需拆分。保留原文不代表任意格式都能自动识别，无法确定时必须人工核对。
- 视觉检查使用了真实 390px iframe 视口和 CSS 200% 放大；原生浏览器 200% 缩放、真实手机与读屏软件仍需发布前复核。没有宣称已建立跨平台像素截图基线。
- 快照只保留最近 20 版，不是长期备份或加密存储；重要学期数据应额外备份。Windows 真机安装包、微信、NapCat 接入和全仓既有失败不在本次 T01 修改范围。
