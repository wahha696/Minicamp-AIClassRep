# 当前需求与架构

更新：2026-10-11。依据当前代码和用户确认的方案。本文覆盖根目录早期《架构.md》《需求文档.md》中的冲突约束；真机步骤见《本地试用验收-QQ微信双源.md》。

## 产品边界

- 当前仓库提供 QQ＋微信统一空间源码；已有 Release 安装包可能早于本次功能，使用本版请按仓库步骤安装。
- 本机有且只有一个固定空间，默认名为“我的空间”，可以改名，不可新建或删除。QQ 与微信连接包含在空间内，登录后自动接入，无需选择空间。每个平台至多连接一个账号，两种平台会话独立管理；更换账号继续使用同一空间的数据。
- 连接页管理空间名称与平台连接、退出；群管理按 QQ 群、微信群、演示与导入分开。QQ 与微信共用群列表、搜索、监听开关、批量开启/关闭与撤销、预设、课程绑定、整理失败重试及删除数据。微信群目录中的未开启群也显示在同一列表，首次开启后可绑定课程；不再显示第二份勾选列表。批量操作仅作用于当前平台，预设按平台隔离并保留已有 QQ 预设。微信群开启操作本身表示同意该群消息读取、保存和按现有 AI 配置整理，直接启动监听，无额外授权勾选或启动按钮；关闭会停止该群，并自动继续监听其余已开启群。启动失败回退选择并尝试恢复原有监听，未实际监听的群显示关闭。微信目录读取集中在微信群页；历史补拉统一为群管理页顶部的「补拉历史」按钮（1／7／30 天），同时补拉 QQ 与微信中已开启监听的群，未开启的群不补拉。AI 配置统一在设置页。
- 微信群尚无本地消息表时仍可开启，持续等待消息；空记录不导致整批失败，补拉历史返回空结果。批量更新期间保留原开关显示并标记正在更新，结束后按实际监听状态显示。顶部微信状态灯在未采集、准备中或错误时统一为红色，仅正在采集时为绿色。
- 用户自行配置 AI 服务凭证：首次引导与设置页复用同一表单，默认 DeepSeek，也可接入任意 OpenAI 兼容服务（填 base_url 与 api_key，模型可留空，检查时自动选用服务返回的第一个）。候选配置通过检查并保存后才继续引导，失败不覆盖旧配置。规则过滤后默认使用本地 fastjudge，可配置 Jev 或双判，随后由大模型提取事件。保留低分过滤策略，不能保证所有重要通知都被识别。
- 手机访问默认关闭，开启后为带访问凭据的只读访问；账号、连接、运行与凭证管理仅在电脑本机执行。
- 手机提醒暂缓：可保存提醒规则，但渠道和绑定未验证，自动发送保持关闭。课代表在启动的命令窗口中前台运行，关闭网页不影响，关闭窗口或 Ctrl+C 即退出。
- 微信仅有 Windows 4.1.15.50 指定模块构建的真机证据，不承诺同版本其他构建或任意新版兼容。

## 数据流与隔离

React/Vite 网页通过 Hono 接口访问本地 SQLite。QQ 通过 NapCat/OneBot 接收；微信通过项目自带 Python worker 进行受控账号核查、群目录查询和所选群读取。

消息进入去重和持久化后，依次经过规则过滤、快判、大模型提取和事件合并。新建、改期、取消保留来源证据；低置信度或与人工锁定字段冲突的变更进入待确认提案。提取或合并失败保留消息供重试，由逐群失败机制限制重复尝试。

跨平台只有正文与关键字段完全相同、且唯一对应的通知才自动合并；相似或冲突内容分别保留。清理群数据时仅移除该群来源，仍有其他群来源的事件保留。

平台登录、退出或更换账号时，接口使用 epoch 租约，异步回调还需核查数据库代次、平台会话和群活动状态。过期响应不得覆盖新的前端租约。退出 QQ 不会退出微信，退出平台不删除空间数据。

微信路径偏好仅写入浏览器 localStorage，键同时绑定服务端提供的安装身份和微信账号；安装身份未取得时不读写，旧版仅按账号缓存不自动迁移。不同克隆共用 localhost origin 不再共享路径回填。该偏好不包含采集权限、账号凭证或聊天数据。

QQ 与微信补历史均由后台任务管理器执行，每个平台在当前目标库中至多一个活动任务，任务身份、逐群游标和计数持久化。HTTP 请求只负责创建、查询、取消或重试；前端持续查询状态，关闭页面不取消，刷新可重新接上已有进度。没有整项任务总超时；仍保留连接失联、进程无响应和游标停滞检测。后端重启或身份变化会将旧运行标为中断，用户核对连接与范围后重试，已入库消息通过原有去重机制保留且不重复。取消在安全边界结束，页面区分已提交、已入库、读取完成与后续 AI 整理。

旧 QQ 和微信空间在启动时合并为单一空间，先保存注册表及业务库的完整 SQLite 备份，并保留次要原库。事件引用随合并重映射；主库的空间偏好优先，冲突业务记录中止迁移，不静默丢弃。保留主库空间标识以维持已有日历 UID。

## 时间与人工操作

课表“第一周周一”只在导入文件与已保存课表均未提供日期时默认 `2026-09-07`。导入日期、已有设置和当前编辑草稿优先，用户可修改；保存仍验证日期有效且为周一。

内部使用毫秒时间戳，展示和无时区 AI 日期按 Asia/Shanghai。只有日期的 AI 时间沿用当日 23:59；非法日期、无效时刻不得自动进位。人工时间限定为非负、可用四位年份导出的整数时间戳。结束时间必须晚于开始时间；无效 AI 改期回滚本批并保留重试，不自行猜测新结束时间。部分回收站恢复若与现有时间冲突，要求用户在详情中修正。

用户修正事件字段后锁定对应字段，后续 AI 冲突先交用户确认；版本增加也可能来自人工修正，因此卡片仅显示“已更新”，不保证来自最新群通知。

人工修改实际内容（含状态、等级）和回收站恢复递增事件版本；只调整锁定设置或内容未变不递增。日历导出保持 UID，SEQUENCE 跟随版本；单条导出取消事件时包含 STATUS:CANCELLED，恢复后移除取消标记。批量导出仍排除取消事件。静态文件重复导入是否更新或删除已有日程取决于日历软件，不等同于订阅同步。

## 桌宠助手与空间偏好

桌宠助手使用用户配置的 LLM，通过服务端类型化工具注册表访问现有应用操作。模型不能指定任意接口地址、shell、SQL、文件或凭据；第三方聊天、页面内容及历史对话不构成操作授权。查询可立即执行，写入、删除和外发操作生成可审阅计划，用户点击确认后才执行。计划绑定浏览器会话、空间和账号代次，过期或换号失效；重复确认复用回执，不重复写入。结果区分真实执行、后台提交及需用户亲自在页面完成的步骤，不将页面交接当作功能已执行。

长期偏好存于当前空间业务库，可查看、修改、停用和删除。普通备注只供助手参考；日程排除规则必须明确课程及事项类型，仅匹配已绑定课程的群，未绑定时不按通知标题推断。规则只影响后续新事项，既有事项的更新、取消及源消息不因排除规则而消失。被排除的候选保存规则、标题与可追溯消息来源，便于核对；主动清理群数据会同时移除该群的排除来源记录，不能借长期偏好继续保留已清理的群原文。

## 存储与外部服务

所选群原文、进度、事件和来源快照可保存在本机；微信发信人显示名取自本机 contact.db 的备注（优先）或昵称，联系人表只在采集进程内存中读取，不落盘，读取失败时显示发信人 ID；微信收件箱当前格式 v4。密钥及完整明文数据库不主动写入文件，不承诺覆盖操作系统分页、休眠或转储。

远程 AI 可能接收通知文本、发送时间、群名、已有事件上下文；偏好总结和页面对话也会发送必要的业务上下文。不能把“程序在本机”理解为“业务内容不离开本机”。Windows 凭证采用现有 DPAPI 机制保护。失败积压和事件证据有独立保留策略，删除原始消息不等于清除全部来源快照与升级备份。

## 验证边界

自动化测试主要使用人工消息、临时数据库、模拟服务和受控进程通信。通过测试不代表微信其他版本兼容、不代表真实手机提醒可用，也不能证明不存在未覆盖缺陷。真实账号、真实消息读取和外部付费 AI 调用需要独立验收。
