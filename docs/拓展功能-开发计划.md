## 0. 需求确认表

| # | 功能 | 已定下的做法 |
|---|---|---|
| 1 | 危机等级 | 4 档：1 低、2 中、3 高、4 紧急。**事件类型决定色相，等级决定深浅**。AI 在提取时给默认等级；用户可在详情里手动调；**手动调过的等级锁定**，群里再来更新也不覆盖（可点「交还 AI」解锁） |
| 1b | 长期记忆 | 每次手动调级都记一条调整记录；由 AI 把全部记录**总结成一句话规则**（如「大物实验报告一律紧急」），提取时作为「用户偏好」喂给 AI。新建「设置」页：记忆开关 + 规则列表（可逐条删）+ 清空。**开关关闭 = AI 不参考规则，但调整照样记录** |
| 2 | 课表导入 | 新建「课表」页：上传学校导出的 xls → 预览 → 确认保存。本学期第一周周一默认 **2026-09-07**，可改。只有 1–10 节（**学校没有 11–12 节**，该行有课时给警告并忽略）；底部「备注」行**忽略**。群 ↔ 课程：默认 AI 按群名猜，群管理页可手动指定。**课表交给提取 AI**，让它看懂「下节课小测」 |
| 3 | 本周两种形态 | ① 按时间从上到下（即现有形态）；② **课程表式网格**：7 列（周一…周日）× 5 行（两节一块），课程作为格子灰色背景，事件落在格子里。**没有课间空档行**：不在上课时间内的事件**归到上一块**（早于 8:00 的归第 1 块）。本周页改为**周一到周日**，可翻到上周 / 下周，标题显示「第 N 周」。两种形态可切换，记住上次选择。课程**只在网格形态作背景**，今日页和纯时间形态都不显示课程 |
| 5 | 待办 | 进待办的三类：① 开始/结束/截止都没有的事件；② 类型为作业（assignment）且只有开始、没有截止；③ 用户手动添加的待办。**打勾 = 完成**（不另做删除）。群里补了截止时间 → 自动离开待办、进日历；群里说取消 → 自动消失。待办框放在今日页，一直在，直到打勾或被群消息更新 |
| 6 | 刷新 | 顶部导航栏全局按钮，点开选 **1 天 / 7 天 / 30 天**，往前补拉群历史消息。**已整理过的消息不再交给 AI**（只补漏掉的）。登录后仍自动补 7 天（保持现状） |
| 7 | 今日两种排序 | 已实现（commit 31c70d6）。本次只改「按紧急」规则：**等级为主，时间为辅** |
| 8 | 展开 | 用在**今日页、本周纯时间形态、本周网格**三处。**同一个节次块**（同一天、`blockOf` 相同）里有多个事件时，只显示最急的一个，右下角显示「…+N」；点开后电脑上在旁边弹出面板，手机上从底部弹出，列出全部事件 |

## 2. 数据库与类型

### 2.1 迁移机制

在 `db/index.ts` 增加：

```ts
function ensureColumn(table: string, col: string, ddl: string): void {
  const cols = db.prepare(`PRAGMA table_info(${table})`).all() as Array<{ name: string }>;
  if (!cols.some((c) => c.name === col)) db.exec(`ALTER TABLE ${table} ADD COLUMN ${ddl}`);
}
```

`openDb` 在 `db.exec(SCHEMA)` 之后依次调用。新表直接写进 `SCHEMA`（`IF NOT EXISTS`）。要求：旧的 `data/classrep.db` 启动后自动升级、数据不丢。

### 2.2 新增列与表

| 表 / 列 | 说明 |
|---|---|
| `events.level INTEGER NOT NULL DEFAULT 2` | 1 低、2 中、3 高、4 紧急 |
| `events.level_locked INTEGER NOT NULL DEFAULT 0` | 用户手动设过 = 1；AI 更新时不改 level |
| `groups.course_name TEXT` | 用户指定的对应课程名；NULL = 让 AI 按群名猜 |
| `todos(id INTEGER PK AUTOINCREMENT, title TEXT NOT NULL, note TEXT NOT NULL DEFAULT '', level INTEGER NOT NULL DEFAULT 2, done_at INTEGER, created_at INTEGER NOT NULL)` | 手动待办 |
| `level_feedback(id INTEGER PK AUTOINCREMENT, event_id INTEGER NOT NULL, group_name TEXT NOT NULL, type TEXT NOT NULL, title TEXT NOT NULL, ai_level INTEGER NOT NULL, user_level INTEGER NOT NULL, ignored INTEGER NOT NULL DEFAULT 0, created_at INTEGER NOT NULL)` | 手动调级记录（记忆开关关着也记） |
| `level_rules(id INTEGER PK AUTOINCREMENT, text TEXT NOT NULL, level INTEGER NOT NULL, feedback_ids TEXT NOT NULL, created_at INTEGER NOT NULL)` | AI 总结的规则；`feedback_ids` 为 JSON 数组 |
| `courses(id INTEGER PK AUTOINCREMENT, name TEXT NOT NULL, teacher TEXT NOT NULL DEFAULT '', location TEXT NOT NULL DEFAULT '', weekday INTEGER NOT NULL, block INTEGER NOT NULL, weeks TEXT NOT NULL)` | 课表；`weekday` 1=周一…7=周日；`block` 1–5；`weeks` 为 JSON 数组如 `[3,4,…,16]` |
| `kv(key TEXT PRIMARY KEY, value TEXT NOT NULL)` | `semester_start`（默认 `'2026-09-07'`）、`memory_enabled`（默认 `'1'`） |
| `message_seen(message_id TEXT PRIMARY KEY, sent_at INTEGER NOT NULL)` | 清理原始消息时留下 id，防止 30 天刷新把已处理过的旧消息再处理一遍、产生重复事件 |

`ai_level`：用户第一次改之前 AI 给的等级。实现方式：`PATCH` 时若 `level_locked = 0`，当前 `level` 就是 AI 给的；若已锁定，沿用该事件上一条 feedback 的 `ai_level`。

### 2.4 共享常量与纯函数

前后端**各放一份**（项目没有共享包）：`CLASS_BLOCKS`（上表 5 块的起止分钟数）、`blockOf(ts)`、`isTodo(e)`。各自写单测覆盖同一组用例，保证两边一致。

```ts
/** 待办判定：状态有效、没有截止，并且（完全没有时间 或 是只有开始的作业） */
export function isTodo(e: Pick<EventDTO, 'status' | 'type' | 'start_at' | 'end_at' | 'deadline_at'>): boolean {
  if (e.status !== 'active' && e.status !== 'pending_confirm') return false;
  if (e.deadline_at !== null) return false;
  const noTime = e.start_at === null && e.end_at === null;
  return noTime || e.type === 'assignment';
}
```

## 3. 后端

### 3.1 危机等级：提取与合并（`pipeline/extract.ts`、`pipeline/reconcile.ts`）

1. zod schema 增加 `level: z.number().int().min(1).max(4).nullable().catch(null)`；`ExtractedEvent` 同步加字段。
2. 提示词输出示例 JSON 里加 `"level": 3`，并新增一条规则（放在 confidence 规则附近）：
   ```
   N. level 是这件事的危机等级，1~4：
      4 紧急：24 小时内要交/要考/要到场，或错过会直接影响成绩；
      3 高：考试、计分作业、必须参加的点名活动，时间在一周内；
      2 中：一般作业、会议、需要行动但不急的事；
      1 低：纯通知、选修/社团活动、可去可不去的事。
      update 时等级没变给 null。
   ```
3. 若记忆开关开且 `level_rules` 非空，提示词末尾追加：
   ```
   用户对危机等级的偏好（优先于上面的一般标准）：
   - 大物实验报告一律 → 4 紧急
   - …
   ```
4. `reconcile.ts`：
   - create：写入 `level ?? 2`。
   - update：仅当 `level !== null && level_locked = 0 && level 变了` 才改，变更写入 `event_history.changed_fields.level`。
   - 自动合并相似事件（已有逻辑）时同理，不动已锁定的等级。
5. `listActiveEvents` 给 AI 的已有事件简表里加上 level，便于 update 时判断。

### 3.2 手动调级与长期记忆

**`PATCH /api/events/:id`**（`routes/business.ts`）新增字段：
- `{ level: 1|2|3|4 }`：写 level、置 `level_locked = 1`、写 `event_history`（`changed_fields.level`）、插一条 `level_feedback`，然后调用 `schedulePreferenceSummary()`。
- `{ level: null }`：只把 `level_locked` 置 0（交还 AI，level 本身不变）。

**新文件 `pipeline/preferences.ts`**：
- `schedulePreferenceSummary()`：防抖 5 秒（最后一次调整后 5 秒才执行，期间再调整则重新计时）。
- `summarize()`：取最近 100 条 `ignored = 0` 的 `level_feedback`，用和提取相同的 LLM 配置（`getLlmConfig()`）调用一次，`response_format: json_object`、`temperature: 0`，要求输出：
  ```json
  {"rules": [{"text": "大物实验报告一律紧急", "level": 4, "feedback_ids": [3, 7]}]}
  ```
  最多 12 条；只总结出现一致倾向的规律，单次偶然调整可以写成针对具体标题的规则。用 zod 校验，成功后**在一个事务里整体替换** `level_rules`。
- 失败或没有 API Key：打一行 warn，保留旧规则，不影响主流程，**不要**计入 `llmStats.failed`（否则会触发流水线全局 60 秒暂停）。

**接口（新文件 `routes/memory.ts`，在 `index.ts` 注册）**：
- `GET /api/settings/memory` → `MemoryDTO`
- `PUT /api/settings/memory` body `{enabled: boolean}` → 写 `kv.memory_enabled`
- `DELETE /api/settings/memory/rules/:id` → 删规则，并把它 `feedback_ids` 对应的记录 `ignored = 1`（以后总结不再用）
- `DELETE /api/settings/memory` → 清空 `level_rules` 与 `level_feedback`

### 3.5 刷新 1 / 7 / 30 天（A 负责补齐，B 负责清理）

**`POST /api/sync`**（`routes/connect.ts`）接受可选 body `{days: 1 | 7 | 30}`，缺省 7（兼容登录后自动补齐的现有调用）；返回 `{groups, messages}`（新入库条数）。**入库完就返回**，不等流水线整理完。

**`ingest/history.ts` 改为分页**：
1. 第一页：`get_group_msg_history {group_id, count: 200}`（不带 `message_seq`，即现状）。
2. 之后每页：`message_seq` = 上一页里 `sent_at` 最早那条的 `message_id`，`count: 200`。
3. 停止条件（任一满足）：本页最早一条早于 `now − days`；本页没有新 id；本页为空或报错（NapCat 找不到锚点会抛「消息 X 不存在」）；该群已翻 30 页。
4. 只入库 `sent_at ≥ now − days` 的消息。

NapCat 4.18.28 源码已确认支持 `message_seq` 分页（传 shortId，内部转 msgId 调 `getMsgHistory`）；**锚点那条是否会重复返回需真机验证**，去重本来就能处理。

**去重**：`ingest/index.ts` 的 `ingestMessages` 插入前同时排除 `messages` 和 `message_seen` 里已有的 id。

**`jobs/cleanup.ts` 改为**（事务内）：
1. 把「`sent_at < cutoff` 且 `processed = 1`」的 `(message_id, sent_at)` 写入 `message_seen`（`INSERT OR IGNORE`），再删掉这些消息。
2. 超过 45 天仍未处理的消息强制删除（同样写入 `message_seen`）。
3. 删除 `message_seen` 里 `sent_at` 早于 40 天的行。

> 不改的话：刚补回的 30 天消息会在下一次整点清理时、还没整理就被删掉。

**`/health`** 增加 `pending`：`SELECT COUNT(*) FROM messages WHERE processed = 0 AND filtered_out = 0`（只算启用的群）。

### 4.6 课表页（新 `pages/Timetable.tsx` + `lib/timetable.ts`）

- **解析库**：SheetJS，**从官方 CDN 安装 0.20.3**：`pnpm --filter web add https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`。**不要**用 npm 上的 `xlsx@0.18.5`（有 CVE-2023-30533）。只在课表页用 `await import('xlsx')` 按需加载，不进首屏包。
- **解析规则（`parseTimetable(rows: string[][]): { courses; warnings }`，纯函数，输入是 `sheet_to_json(ws, {header: 1, defval: ''})` 的结果）**：
  1. 找表头行：包含「星期一」…「星期日」的那一行，**按表头文字定位每一列**（样例里星期日在第一列，别写死顺序）。
  2. 表头之后，第一列匹配 `/^(\d+)\s*[－\-–]\s*(\d+)$/`（注意样例是**全角「－」**）的行是节次行：`1–2→块1`、`3–4→2`、`5–6→3`、`7–8→4`、`9–10→5`；`11–12` 行若有课，产生 warning「第 11–12 节不在作息表内，已忽略：xxx」。
  3. 第一列以「备注」开头的行，以及其他行，一律忽略。
  4. 单元格内容 trim 后为空则跳过。一个格子里可能有**多门课**：按行切分后，以「周次行」（匹配 `\[周\]`）为锚点切段，每段依次是：课名、教师、周次、教室（教室可能为空，如样例里的体育）。
  5. 周次解析：去掉 `[周]` 后按 `,` 分段，每段是 `n` 或 `a-b`，可带后缀「单」「双」（只取奇数周 / 偶数周）。例：`3-16` → 3..16；`8,12` → [8, 12]；`1-15单` → 1,3,…,15。解析失败的给 warning 并跳过该门课。
- **页面流程**：选择文件 → 解析 → 显示预览网格（同 `WeekGrid` 的样式，只读）+ warnings 列表 + 「第一周周一」日期输入（默认已保存值或 2026-09-07，必须是周一）→「保存」调 `PUT /api/timetable`。已有课表时显示当前课表、「重新导入」「清空」（清空走 `ConfirmDialog`，**默认焦点放在「取消」**）。

## 8. 风险与真机验证

- **分页行为**：`message_seq` 翻页、锚点是否重复、翻到群最早消息时的报错形式，必须在 Windows + NapCat 真机上验证后再合并第 5 步。
- **AI 费用**：30 天刷新时一个活跃群可能有上千条消息；大部分会被规则和 Jev 滤掉，剩下的仍有可观调用量。按钮旁已有提示，勿改成默认 30 天。
- **提示词变长**：课表段 + 偏好段每次多几百 token，延迟和费用略增，用 eval 确认。
- **流水线暂停机制**：目前任何一次 LLM 失败都会让所有群暂停 60 秒（`scheduler.ts` 的 `llmRetryAt`）。偏好总结的失败**不能**走这条路（见 3.2）。
- **隐私**：课表 xls 含真实姓名和学号，**不要把原始 xls 提交进仓库**；测试一律用附录 A 的脱敏样例。
- **跨人改动**：第 2 节的表、类型和第 5 节的接口按总约定要四人同意，开工前先发到群里确认。
